## ⚠️ 文档中的数字均为占位值

设计文档与原型中出现的**全部指标均为设计阶段的占位值，不是实测结果**：

- 执行准确率 `89.2%`、静态校验拦截率 `34.6%`、单次成本 `¥0.011`
- 消融实验四组数据、各步骤耗时与 token 数
- 原型中的查询结果表格（基于样例库结构虚构）

这些数字用于说明**将要度量什么**，而非**已经度量到什么**。
**这些文档不会被回填** —— 它们是当时的设计稿，改掉就失去了对照价值。

**四个例外**（数字是实测的，适用主 README 那条原则）：
`test-report-agent-soak.md`、`test-report-schema-recall.md`、
`design-agent-trace-optimization.html` 与 `design-agent-trace-af565a7a7074.html`。
两份提效方案里的每一个数都能回溯到生产 trace（`4bac5ce7f21b` / `af565a7a7074`）的
span 明细、`/api/audit` 的分布抽样或 `config/public.yaml` 里的单价（标为"预估"的只有
改造后的目标值）；召回基准的数由 `python -m evals.recall` 现场跑出，原始结果在
`evals/results/recall.json`。

实测结果在主 README 的「实测结果」一节，P3 完成后已按承诺公开：盲测集成绩
（实现全程不可见、一次性运行，该成绩即最终成绩）、未经筛选的失败样本分类分布、
以及各消融组与准确率同时报告的成本与延迟代价。原始结果在 `evals/results/`。

主 README 的原则同样适用：**不会出现未经实测的指标。**

## 产品原型

原型是**产品目标**，不是当前版本的说明 —— 它有意画得比已建成的多。三组导航：

| 分组 | 页面 | 状态 |
|---|---|---|
| Workspace · 阶段一 | 查询工作台 / 任务中心 / 数据源 | 已建成 |
| Governance · 阶段二 | 身份与权限 / 业务口径 / Agent 质量中心 / 执行追踪 / 审计中心 | 已建成（「高成本审批」入口 2026-09-06 撤下，页面与接口保留） |
| Scale · 阶段三/四 | Connector 节点 / 开发者工具 / 产品落地路线 | **未实现，无后端** |

看原型时优先看这几处，它们是这个项目区别于"能写 SQL 的聊天框"的地方：

1. **查询工作台的右栏** —— 生成的 SQL 里，租户谓词与 `LIMIT` 被标为系统强制注入，
   一眼可辨哪部分是模型写的、哪部分是护栏加的。
2. **任务中心的断点续跑** —— 从检查点恢复，checkpoint 之前的节点不重跑。
3. **业务口径中心** —— 模型永远推不出来的那一层，也是消融实验里唯一有方向性收益的一组。
4. **审计中心与执行追踪** —— 每次调用一条记录，包括被护栏拦下的那些。

与已上线控制台的对应关系见主 README 的「Web 控制台」一节。
