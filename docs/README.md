## ⚠️ 文档中的数字均为占位值

设计文档与原型中出现的**全部指标均为设计阶段的占位值，不是实测结果**：

- 执行准确率 `89.2%`、静态校验拦截率 `34.6%`、单次成本 `¥0.011`
- 消融实验四组数据、各步骤耗时与 token 数

这些数字用于说明**将要度量什么**，而非**已经度量到什么**。
实测结果将在 P3 阶段（黄金集 58 题 + 五组消融）完成后回填，届时同步公开：

- 盲测集（18 题）成绩 —— 实现全程不可见，一次性运行，**该成绩为最终成绩**
- 失败样本的分类分布，不做筛选
- 各消融组的成本与延迟代价，与准确率同时报告

主 README 的原则同样适用：**不会出现未经实测的指标。**

## 交互原型 · 三个页签

| 页签 | 看点 |
|---|---|
| ① 接入数据 | 三步向导。第 1 步的连接自检包含一项**写操作实探** —— 主动发起 INSERT，必须被拒绝才算通过 |
| ② 提问 | 生成的 SQL 中，`org_id` 与 `LIMIT` 以**高亮标注为系统强制注入**，一眼可辨哪部分是模型写的、哪部分是护栏加的 |
| ③ 评测 | 消融实验四级阶梯（占位数据） |

「② 提问」页的四个示例分别对应四种情形：

1. **命中业务口径** —— 复用「卡住的文档」判据，无需重新描述
2. **多步规划** —— 先探明失败率分布，再用得到的 `kb_id` 拉明细
3. **看似多跳、判定单步** —— 依赖关系可用 CTE 表达，走多步属于误用
4. **危险操作拦截** —— 模型生成了 `DELETE`，在 AST 层被终止

第 2 和第 3 个示例需要放在一起看：前者证明多步有用，后者证明多步会被滥用。
只有前者等于在鼓励滥用。
