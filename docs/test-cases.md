## 说明

**「现状」列是设计阶段的估计，不是实测结论。**执行时须逐条核对并回填 ——
标「已覆盖」的若实际没有对应断言，等同于未覆盖。

- **类型**：正常 / 边界 / 异常 / 安全 / 回归
- **优先级**：P0 = 不通过即阻断发布；P1 = 影响正确性；P2 = 体验与一致性
- **回归**：来源于已发生过的真实缺陷，编号后标 `↩`，这些一条都不能删

**设计取向**：本项目的核心命题是"在模型不可靠的前提下让链路可靠"，
因此用例重心不在"模型答得对不对"，而在**护栏是否拦得住、改写是否绕不过、
失败是否诚实**。凡涉及模型输出的用例一律用假模型（FakeLlm）注入确定内容，
不依赖真实密钥，也不允许因模型抖动而结果不定。

## 评审关注点（需要确认的设计约定）

以下几条**用例写不下去，因为设计本身没定**。执行前需要先定夺，否则测出来
的"预期结果"是我替产品做的决定：

1. **H-17 跨租户切换的边界**：接口允许调用方任意传 `org_id`，应用层按传入值
   注入、RLS 按会话变量兜底。那么"传他人 org_id"到底算越权还是算正常授权
   切换？本工具不设账号体系，边界只能落在部署方 —— 但文档没写明。
2. **F-08 / F-12 空问题与零召回**：目前行为未约定。是拒绝、还是注入全量
   schema 让模型自己判断？两种都合理，但必须选一种并写进文档。
3. **F-10 token 预算超限**：设计文档 §3.2.3 要求"截断并记录告警"，
   实现里只读了预算值，**未见告警**。这条是先补实现还是先降要求，需定夺。
4. **K-08 配额触顶对评测的影响**：历史上出现过配额中途触顶导致 23 题被判
   QUOTA 失败、污染成绩。现在是否已把 QUOTA 失败从准确率分母中排除，
   需要确认；若未排除，这是评测方法论上的硬伤。
5. **C-17 org_id 类型校验**：接口层是 `int | None`，但 MCP 与内部调用路径
   是否都有同等强度的校验？若任一路径能传入字符串，就是注入面。

## 执行约定

- **不依赖真实模型密钥**：涉及模型的用例一律用 FakeLlm 注入确定输出。
- **不依赖生产库**：默认跑在本机样例库；标注"PG"的用例单独一组，
  在隔离环境执行，**绝不指向生产主库**。
- **回归用例（↩）不得删改**：每条都对应一个真实发生过的缺陷，
  删掉等于把已修的 bug 放回来。
- **失败必须留证据**：断言失败时输出实际值与 trace_id，便于用
  `askdb replay` 复现。
