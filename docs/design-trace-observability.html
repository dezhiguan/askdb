1问题

现版本 Trace 详情页把链路的终态渲染出来，而不是链路的经过。三个后果： Span 状态列只有一个取值 OK，被重试救回来的失败在页面上完全消失； 模型格只显示最终生效的模型，主模型超时切备用模型没有任何痕迹； 工具调用格只有次数没有成败，返工掉的耗时与 token 被并进总数。 结果是一条降级完成的链路，看起来和一条干净链路一模一样 —— 而这类链路给出的答案恰恰最不该被直接采信。

3相对现版本的改动点

  1. 状态枚举从一元扩到五元。现版本 Span 状态列只有 OK，被重试救回的失败在页面上完全消失。新增 FAILED / FALLBACK / DEGRADED / EMPTY，失败的尝试作为独立 Span 保留，不被成功的那次覆盖；Span 名后挂 尝试 n/N · <模型>。
  2. 模型格显示回退链而非终态。主体显示实际产出模型，下方标注 ⇄ 回退自 <主模型>，主模型名加删除线，格子带橙色下划线作为可扫视信号。
  3. 工具调用格拆出成败。次数之下补 n 失败 · m 降级；耗时与 Token 同步区分「有效」与「重试废弃」，避免用总数掩盖返工成本。
  4. 顶部异常横幅只在非纯净链路出现。三条事实句给出：哪个环节失败、回退到什么、代价是什么。纯净链路不渲染该区块，日常不增加噪音。
  5. 空结果与上游降级联判。只读执行返回 0 行时一律标 EMPTY；若链路上还存在 FAILED/DEGRADED，在输出摘要与顶部横幅中明确「不可判定为无数据」。可信度徽标不动，另挂一枚「链路降级」角标 —— 理由见下节。

4与可信度分的边界

本设计成稿时，追踪页那枚角标还是写死的「可信度 —」。落地当天该版位已被另一条线做成真打分 （frontend/src/trust.ts，通过率模型：分数 = 通过项 / 适用项，每项都是链路记下的事实， 明确拒绝加权扣分）。本设计因此改为不动那个分，在它旁边另挂一枚「链路降级」角标。两条理由：

  1. 把降级折成扣几分，等于给通过率模型塞一个没有出处的权重。「回退扣 10 分」的 10 从哪来说不清， 而该模型正是为了避开这种数字才写成通过率的。
  2. 降级角标说的是事实，不是判断。「主模型超时切了备选」能从 span 上逐字读出来， 它不需要先被折算成一个分数才成立。
遗留缺口 · 需另行定夺

可信度分目前判不到回退与降级。trust.ts 那六项取自审计记录的字段 （截断 / 重试次数 / 脱敏降级 / 召回盲选 / 结果行数），主模型切备选、向量召回回落只留在 span 上，一项都不占。 于是会出现「可信度 100 + 链路降级」并排的组合 —— 两枚角标各自都没说错，但读的人有权问这个 100 是怎么来的。 要闭合的话，自然的做法是给 resultChecks 增加「模型未回退」「Schema 召回未降级」两项， 由 span 派生后与既有六项同权计入分母。本设计不擅自改动该模块 —— 它由另一条线在迭代，口径变更应由其定夺。

5前置依赖与风险

阻塞项 · 已查实（V1.1 回填）

本设计假设后端真的保留了失败尝试的 Span。查实结果比预估更深：回退与重试整个发生在 LlmClient 内部，Tracer 在外面只拿得到最后返回的那个结果 —— 主模型超时、切备选、切成功，三件事在审计里一件都不剩，不是被覆盖，是从来没写过。
连带查出一处更硬的缺陷：审计记录里的 model 直接取 cfg.llm["model"]，即配置声明的主模型。切备选跑完，库里照样记着主模型 —— 页面看不出回退只是表象，存下来的那条记录本身就是错的，按模型分摊的成本也跟着记到了没出活的那个头上。

Span 记录实际落的字段：attempt / attempts_total（第几次尝试 / 共几次）、 status（三档口径，见下）、error_code（厂商状态码，取不到才退回异常类名）、 disposition（切备选 / 就地重试 / 回落备用路径），以及按次记的 model。 原始错误消息复用既有的 note 字段，不在后端截断 —— 截了就再也拿不回来，截断交给前端。
废弃 token 不另设字段：失败的那条 span 自己带着这次真实烧掉的 tok_in/tok_out， 成功那条只记它自己的。前端把失败 span 的 token 加起来就是废弃量 —— 多一个冗余字段， 就多一处会和 span 对不上的地方。
落盘时零值字段一律省掉（沿用 tables 既有做法）：绝大多数步骤只跑一次、没失败， 每条审计凭空多五个键，乘上几十万条不是小事。

6分阶段落地

阶段一写入侧留痕2026-09-11 ~ 2026-09-16

  • 核实重试路径是否覆盖同一 Span；若覆盖则改为追加。
  • 补齐 attempt / disposition / tokens_wasted 字段与五元 status。
  • 模型名下沉到每次尝试，链路级模型字段改为「最终产出模型」。
  • 验收：人工制造一次上游 504，库中能查到两条 SQL 生成 Span。

阶段二详情页呈现2026-09-17 ~ 2026-09-23

  • Span 表状态列五元着色 + 失败行默认展开错误详情。
  • KPI 区模型回退链、工具成败拆分、耗时与 token 的有效／废弃拆分。
  • 阶段条失败态与 ×n 重试角标。
  • 顶部异常横幅（纯净链路不渲染）。

阶段三空结果联判与可信度口径2026-09-24 ~ 2026-09-30

  • 零行结果与上游降级联判，落 EMPTY 状态。
  • 非纯净链路挂「链路降级」角标，悬停说明降在哪几处（不改动可信度分，理由见第 4 节）。
  • 回归：覆盖工具失败、模型回退、零行、纯净四类链路各一条。
