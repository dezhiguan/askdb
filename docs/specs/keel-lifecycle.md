# AskDB 的 Keel 生命周期接入（2026-10-25）

目标：保留业务图、SQL 护栏、数据源白名单及行级权限，平台调用统一使用 Keel SDK 的运行协议、模型、提示词、追踪、审计、评测及版本发布。原 HTTP 入口保留，旧记录按影子迁移口径保留。

范围：新增受治理运行适配、提示词副本与清单、平台评测种子及评分器、部署配置和接入/验收脚本；修复旧影子模型路径要求厂商密钥的问题。补齐现有测试在不支持 FastAPI telemetry 的版本上的兼容断言；最终完整回归使用不含开发 .env 的干净工作树，避免真实元数据库混入测试。不修改底座契约或新增控制台页面，使用既有注册、调试、提示词、评测、追踪、审计和发布页面。

实现：KEEL_ENABLED=1 时启动失败即明确报错，不吞配置错误或删掉 models。业务同步图在工作线程运行，以每次调用独立的 ContextVar 桥接同一个 ctx.llm、ctx.prompt 和 ctx.audit，模型结构化工具输出保留 pydantic 校验，网关执行授权/预算/路由。提示词完整模板入 prompts，动态变量与原模板保持一致；generation 关联实际提示词版本。调用返回真实回答和结果行，错误由 SDK error 事件传播。平台用户身份只读取受信调用上下文并按 askdb 用户角色收窄，禁止输入自行指定角色/租户。调用节点通过 SDK step 事件展示。迁移期间不删除旧追踪、审计、审批及评测。

验证：提示词渲染等价、结构化模型及错误传播、并发调用隔离、审计白名单、真实 SDK invoke/SSE、缺配置启动失败；askdb 完整回归；目标集群 staging 注册、真实模型/数据库调用、控制台同源调试 SSE、平台提示词/评测/追踪/审计证据。未执行或失败的检查如实记录，不以 mock 代替线上验收。发布遵守现有平台候选/门禁机制。
